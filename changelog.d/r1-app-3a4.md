- Added: On macOS, Halvo keeps a login item that it has written in line with itself and says on its page when launchd does not hold it. When Halvo starts on a data directory that its capture service has set up, it writes its login item (com.halvo.desktop.plist in your LaunchAgents folder) again wherever that file is not what Halvo writes, whether in its bytes, its mode, its owner or as a link, so a copy that you changed by hand is written over; it writes none where none stands and none while macOS runs Halvo from a temporary location. It then asks launchd once, from the exit status of `launchctl print`, whether it holds the item, and where launchd does not hold it while the file stands, the capture page says in one line that Halvo should start by itself when you log in and where to turn it on in System Settings. `halvo --write-login-item --login-label LABEL --data-dir DIR` writes such a file under another label into DIR for tests; it exits 64 and writes nothing for the real label or the default data directory.
