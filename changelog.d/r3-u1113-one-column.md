- Fixed: (agents run, U11.13) On a computer whose own decimal sign is the comma, a data file of one column of numbers with a decimal comma (3,5 on a line) or of amounts with a money sign (41,20 €), with or without a title line, fills cells that are one column wide, each number with its decimal part; a value such as 1,250 in it lands as text, and so does each amount with a money sign beside it, and the row says how many values it wrote as text. Before, Halvo read each such number as two values, and the row said that the data did not have as many rows and columns as the cells, or that Halvo could not read the data file. Such a file reads as before where the cells are two columns wide, on a computer whose decimal sign is the point, and where Halvo cannot read that setting. In a file saved as neither UTF-8 nor UTF-16, an amount that holds a character that is not ASCII, such as a euro, pound or yen sign or a no-break space, lands as text where another line of the column is a number with a decimal comma (12,00), and where no other line is one, the file reads as before.
