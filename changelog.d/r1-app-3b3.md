- Added: (capture run, app-3b3) On macOS, on a data folder that its capture service has not set up, the app shows a first-run text with one Start control and starts nothing before that click: no capture service, no store, no state file, no key file and no login item. The click is the consent: through the new command start_capture it writes the login item (none with --data-dir), starts one capture service, waits up to 10 s for its status and turns capture on only when no permission step is open. A data folder whose name leads nowhere, is not a folder or cannot be read shows its cause and never the consent. Every sentence of the first-run text comes from halvo-control's table (texts::first_run), among them that Halvo looks through what it recorded for tasks that repeat, on this computer alone.
- Changed: (capture run, app-3b3) halvo-control's table of what Halvo records starts with a row that no switch turns off, "Halvo records which app is in front, each time that changes.", and the row of the switch pointer_class reads "Halvo records each click and which button you pressed, and how many times you scroll, drag or move the pointer each second, never where on the screen."; the first-run text and the data view show both. A row's switch is optional in the table and reads null on the wire for that first row. The constant TYPING_ON_MAC moves from the capture crate's macOS input source to halvo-control's texts module, which the capture crate re-exports.
