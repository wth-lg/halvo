- Security: (capture run, sqlcipher-2; RUSTSEC-2026-0502) Every Halvo crate that opens an encrypted database now links SQLCipher 4.20.0 on SQLite 3.54.1 (sqlcipher-src 420.0.0, with rusqlite 0.42.0 and libsqlite3-sys 0.40.0): when the database reads a page from a write-ahead log whose pages are smaller than its own, it fills the rest of the page with zeros instead of leaving earlier memory of the process there. The capture store opens only when the library reads back as version 4.20.0, the two page-gap statements of the build were read again in the new source with every row of the table of ADR 0013, and deny.toml no longer ignores the advisory. The capture store sets SQLCipher's log level to NONE before it sends the key, where before it set it after the first read, so a refused open (a wrong key or a damaged file) no longer writes SQLCipher's own lines to the system log on macOS or to the error output on Windows. A test reads the level and, on Windows, the error output; no test reads the macOS system log.
