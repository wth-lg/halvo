- Added: (interface run, U3.4; rulings RD-19 (c) and (d), RD-30 (1), RD-31 (4), RD-64 1.6 (b), RD-78 E24, RD-152 (4)) The delete of an agent. In halvo-coord and halvo-coord-app, the page command agents_delete with the argument agent and the causes state, unknown_agent, no_service, busy and malformed, and the owner's port Owner::delete for the decision delete of a workflow (W-C3.10), whose default answers no_service and which the wrappers Watch and Wired hand on. With no run of the agent on the board the core sends the decision at once, after a queued start leaves the queue, and the agent's row leaves the state; with a run on the board it stores the hold off, stops the run as the switch-off does, keeps the intent in memory alone and sends the decision once that run's run_ended is stored, the row showing the line working.deleting with no control until then; an agent whose record is stuck is stopped as Stop stops it and its delete is sent once the run has left the board; the first step of the quit forgets every intent, so nothing is deleted and the agent stays switched off. Each row with Delete carries in its key ask the words of the page's own question: with no live run the question names the agent and its next day, says what is removed from Halvo, that it cannot be brought back, that nothing already paid, ordered or sent is taken back and nothing at a website cancelled, that the copies beside the workbooks stay and that a task that starts before the answer is stopped first, and shows each effect of the last run whose outcome is not known with its kept fields and the sentence that Halvo keeps no record of it, with Keep it and Delete; while a run is live it is a notice with Let it work and Stop, and while the run stops a notice with OK. Behind a take-back of an agent that asks first, the row of the ready card that comes back says that the start was cancelled and that the agent asks again. In the page, ui/app/views/confirm.js, the one helper of a page confirmation that both views load: the record of presses, the dialog and its press rule, one confirmation open at a time for the whole page, and the status element of both views. The agents view draws Delete and Cancel this start from the row's controls; a press on Delete sends nothing and opens the question, whose unsafe control alone sends agents_delete, once, and a page confirmation that arrives while it is open waits behind it.
