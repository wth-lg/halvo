- Changed: On Windows `halvo-capture --delete-all --data-dir DIR` now deletes everything with no capture service running, in a release build as in a debug build, where it answered usage (exit 64) before; so the program no longer needs the running service for Delete everything on Windows, while the app there still asks the running service until a later change of the app. It has the words and the exits of a Mac: `data_dir=` and the `deleted` line on standard output and exit 0 once nothing of the store but its empty writer lock file (store/writer.lock, which holds no data), nothing of its key and its root and nothing of the registry's other rows stands (the rows run and logs keep their files), and every folder that the delete flushes reached the drive; or the busy line and exit 75 with nothing deleted while a service holds the directory. The delete first takes the program out of Windows Error Reporting, as every Windows run does, then opens the store under DPAPI, whose own delete runs before the delete on the directory. Where Windows refuses that exclusion, a line on standard error says so, and the delete opens no store, unprotects no root and unwraps no key: the store goes by the delete on the directory alone, and the `deleted` line reads `segments_shredded=unknown keys_destroyed=unknown`.
- Fixed: On macOS `halvo-capture --delete-all --data-dir DIR` exits 1 where a folder that the delete flushes did not reach the drive, with that folder's line on standard error, as the capture service's own delete reads such a finish; it exited 0 there, while delete-all.intent stayed and the next start of the service ran the delete again. On Windows the offline delete has this exit from its first form.
