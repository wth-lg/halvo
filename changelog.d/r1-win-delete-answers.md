- Fixed: Where a file of the store stays after a delete, every answer of the delete now says so. `halvo-capture ctl delete-all` exits 1, on both systems, wherever its `deleted` line reads `files_left` or `entries_left` above 0 or `database_left=yes`, with one line on standard error that names what stays, such as `halvo-capture: the delete is not finished: other files of the store that stay: 1; registered entries that stay: 2`; before, it exited 0 there unless the root survived. On Windows a delete through a store handle, the service's own delete and the offline delete where the store opens, reads whether the store's lock file still stands behind the handle's close with the store's own reader, the one that the delete's tail asks too, which takes every answer but no such entry as standing. On Windows a second press while another program keeps the marked lock file open no longer says that store.key and a database file stay where the delete before it removed both: a delete that cannot take the store's lock reads the store's files as they stand and removes none, and standard error says `halvo-capture: the delete is not finished: another program holds the store's lock file open; the folder roots could not be listed; other files of the store that stay: 1`.
- Changed: The line of a delete that is not finished prints the count of the store's other files behind its words, `other files of the store that stay: 1` in place of `1 other files of the store stay`. The store's own two registered entries, which stay until the delete of the store finishes, get their own line, `halvo-capture: registered entries of the store that stay until the delete of the store finishes: 2`; the line `<n> registered entries stay; a process that a pid file or a run's mark names did not end, or their files could not be removed` counts the other entries alone. The field `entries_left` keeps its count.
