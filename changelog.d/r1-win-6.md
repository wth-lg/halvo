- Fixed: On Windows the keyboard source's password gate clears a key only after the program in front has shown that it took input: a value-change event that the focused field itself raised at or after the key's time, read as no password field, with the gate's own read of the focus a hold after it. A key typed ahead of a focus move that no latch sees (the program's own move, a page's own move, a field that turns into a password field on a page that holds its thread, an access key) is no longer recorded when it lands in a password field: the five tests of those cases leave the list of known defects and read 0, and new phases hold the access key, a password edit that raises no event and a page field that changes its value by itself. A landing clears no key that stood before a change of the focus (a focus event, a latch or a read that shows a move between them). A key that changes no text has no landing: it is withheld at 250 ms and sets keys_withheld. One sequence stays open and stands as a known defect (W6-own-change): a program that changes the text of the focused plain field by itself before it takes a queued key, works more than 120 ms, then moves the focus to a password field and takes the key there; its twin without the program's own change records nothing.
- Changed: On Windows a key behind an open latch (after Tab, Enter, Escape, a Windows key or a button-down) is recorded on its own landing made after that latch, so a program that acts at once no longer withholds every key after such a key.
- Added: The status of a daemon whose keyboard source runs on Windows carries `typing_gate` (`ok`, `field_unknown` or `latch_open`), and `halvo-capture ctl status` prints it as one line behind `keys_withheld`; a Mac reports none.
