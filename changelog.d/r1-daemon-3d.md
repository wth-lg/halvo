- Added: (capture run, daemon-3d) In a debug build on macOS, `halvo-capture --delete-all --data-dir DIR` deletes the data of a data directory with no daemon: it takes the instance lock, opens the store as the custody policy says (a store that does not open, that the policy refuses or that it opens for maintenance alone is deleted all the same), writes delete-all.intent through the durable-write helper, clears the mark store_made, deletes the store root first, then every other row of the registry in table order (the process that a row's owner pid file names is ended first, its key files go through the store's key-file helper and its entry is removed), counts and leaves the entries that the registry does not know, flushes the folders, and removes the intent only after a whole finish. It prints data_dir= and then no_store or the deleted line, and exits 0 once the root and store.key are gone, 1 when something stays, with the intent kept and the cause on standard error, and 75 with nothing removed while another process holds the directory or the store. The store port gains StoreHost::delete and MaintainStore::delete_all.
- Changed: (capture run, daemon-3d) A service run that finds delete-all.intent finishes that delete before its open's first call, also where the data directory failed its check, because a failed check never gates a delete; while the delete runs the slot reads Deleting. After a finish that is not whole (a store that another process holds, a root that stays, a failed flush or a failed removal of the intent) the intent stays, that run opens no store, and the next start tries again. Check 30-core-boundary-proofs lists crates/halvo-capture/src/daemon/delete_all/process_tests.rs among the daemon's test-support files.
