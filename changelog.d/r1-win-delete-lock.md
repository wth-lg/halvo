- Fixed: On Windows, a whole Delete everything no longer leaves the empty lock file store/writer.lock of the deleted store in the data directory; behind the service's own delete, the fresh store that the service then makes has its own lock file at that name. This holds for the service's own delete and for the offline `halvo-capture --delete-all --data-dir DIR`. Where a delete leaves nothing else in the store folder, the store's writer lock marks its own file for removal while it still holds the lock. The file goes when the lock closes, and Windows refuses every open of the name until then, so no other process takes the lock in between. Where the name still stands behind the close, because another program keeps the file open, the file counts as left and the delete is not whole: the deleted line reads `files_left=1`, delete-all.intent stays, and the offline delete says `the delete is not finished: other files of the store that stay: 1` on standard error and exits 1; a second press ends it once that program has closed the file. So exit 0 of the offline delete now means that nothing of the store stands, its lock file included. The store folder itself stays, as on a Mac. On a Mac nothing that a person meets changes.
- Changed: On Windows, an offline Delete everything on a data directory where nothing of the store stands but an empty store/writer.lock now removes that file and prints the deleted line, with `root_destroyed=unknown` and exit 0; before, it printed `no_store` and left the file. The scratch delete `--delete-all --store-dir` of a debug build removes its lock file too.
