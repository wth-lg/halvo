- Added: (capture run, win-5 cut 2a) On Windows, in a debug build alone, `halvo-capture.exe --service-run --data-dir D` runs the capture service: it listens on the named pipe of D, answers `ctl status`, and ends with status 0 on `ctl stop`, the one request that ends it in this cut. Its Status names the platform windows, the six Windows source lines with the keyboard, the screen and system_audio off, the password guard none, keys_withheld no, the custody dpapi and the service's own peak working set. Its sources are the foreground, the pointer and the window title, which start only on the run condition; it makes no keyboard source, no screen source and no system_audio source whatever the state file's switches say. A fresh store lies under D, its key file in D\store and its one DPAPI-protected root file in D\roots.
- Changed: (capture run, win-5 cut 2a) On Windows a debug build's `--service-run --lifeline` says that the lifeline mode is not built on this system and exits 1 before it takes the data directory, and `--service-run --scripted-sources` says that the scripted sources are not built on this system and exits 1; before, both answered that the service run was not built.
- Fixed: (capture run, win-5 cut 2a) On Windows the delete walk ends a running owner that a row's pid file names before it removes any of the row's files: one handle opened by the pid, the process's start time read on that handle and compared with the pid file's, then the process ended and a wait of at most 5 s. Before, a Windows build read every owner as gone and removed a row's files under a live owner.
- Removed: (capture run, win-5 cut 2a) The Windows custody's roots directory under %LOCALAPPDATA%\Halvo, which no caller used; no file of the custody reads LOCALAPPDATA.
