- Added: On Windows, the control channel of the capture service: the named pipe of a data directory (`\\.\pipe\halvo-control-<SID>-<hash>`), made as its first instance only, with remote clients refused, at most five instances and access for the user's own SID alone. Its server drops a client whose process runs as another user, with no read of its request and no reply; its client opens the pipe with identification-level impersonation and refuses a server whose process runs as another user before it writes a byte. halvo-control also gains one way to start a program on Windows with its three standard handles, an explicit list of further inherited handles and no console window. No service run on Windows serves the pipe yet, and the app on Windows still says that capture is not available there.
- Changed: On Windows, `halvo-capture ctl` in a debug build asks the pipe of its data directory: with no capture service there it prints that the capture service is not running at the pipe's name and exits 69, where it said that the control channel was not available on Windows yet and exited 1. The merge gate runs the two unit tests of halvo-control that read the Windows pipe client and the child start (scripts/ci/slow-tests.txt).
