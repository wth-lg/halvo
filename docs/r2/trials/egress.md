mechanism sandbox: sandbox-exec runs the command under a profile that allows everything but outbound network operations; it denies every outbound connect and send to an IP address, sends on ICMP and ICMPv6 sockets, the connect to the resolver's socket /private/var/run/mDNSResponder and the lookup of the resolver's service com.apple.dnssd.service, and allows each entry 127.0.0.1:P of the list as the one rule ip4 localhost:P (the profile writes no ip6 rule); a deny rule carries the run's token, and a log stream between two marker denials collects the kernel's reports into denied.log
mechanism sandbox lookups: a program that resolves a name through the system's URL loading (nscurl, a web view) reaches the resolver through its service com.apple.dnssd.service and not through its socket; the profile denies that lookup and logs it as proto=dns with the image of the process (probe resolver)
mechanism sandbox handed-off: the profile denies the lookups of com.apple.nsurlsessiond and com.apple.nsurlsessiond-launchondemand, which make the transfers of a background URL session, and logs each as proto=- dest=-:- with the image of the process that asked (probe session); a program that uses the system's URL loading looks the service up also for an ordinary session, so its run exits 1 with that line; the launch service's daemon and every other service stay allowed, so that the programs that later runs wrap still start; it also denies the operation lsopen, through which the launch service has another application open a URL or a file, and logs it the same way with the image of the process that asked (probe open, run on the hosted runner alone: in run 43099680165 it ends denied at the head and missed at ab0c3e9, which has the probe and not the rule)
mechanism sandbox listen: the profile denies no bind, listen or accept, so a process of the tree may listen on a listed loopback entry; a connect from the tree to that entry is allowed by the entry's rule
mechanism sandbox entries: the profile names a host only as localhost, so the mode takes the entry 127.0.0.1:P alone and refuses with the cause entry every other host, a routable address and 127.0.0.2 included; it refuses [::1]:P too, because the rule ip6 localhost:P also allows the IPv4-mapped ::ffff:127.0.0.1, so 127.0.0.1:P would be reachable outside the list
mechanism sandbox reports: the kernel's report names the process and its pid, the port, and whether the host is loopback, not the address, so a denied attempt to a host other than 127.0.0.1 is logged as dest=-:<port>, an ICMP send as proto=icmp dest=-:-, and the self-test reads an address - as the probe's; the kernel folds repeated reports of one process to one port into one line, which the log expands to one line per attempt with proto - and dest -:<port>
mechanism sandbox run directory: the profile denies the tree every write under target/egress and scripts/egress and every signal to a process outside its sandbox; the runner reports the command's status on a pipe that the command does not inherit; a marker counts only from a line of the kernel's Sandbox reports, and the check refuses with the cause mode when the log stream that it started is not alive at the end marker or a script or binary of the check changed during the run; a marker counts only in a report whose whole message is that of the check's own marker process, the runner's name with the process id of that marker run, a network-outbound denial and the run's token with the marker word, with no line break before the token, so a process name or a file name that carries the marker's text is read as a denial (tests newline-in-a-process-name and end-marker-in-a-file-name, evidence/builder-9/runs/q2-after-test-sandbox.txt)
