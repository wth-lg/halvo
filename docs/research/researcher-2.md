# researcher #2: Self-improvement that is usable on a laptop
STATUS: ISSUES
now: 2026-11-09    stale cutoff: 2026-05-09    lane: 2

## Summary
- **Refinement without training (sub-question 1).** The published line that fits a laptop is context and memory editing, not weight updates: Agentic Context Engineering (#31, v3 2026-03-29, ICLR 2026) keeps an itemized playbook updated by small deltas from execution feedback and needs no labels; GEPA (#33) and Dynamic Cheatsheet (#40) do the same for prompts and reusable snippets; Agent Workflow Memory (#42) induces reusable workflows from past web-task trajectories; Voyager (#43) and Reflexion (#44) are the origins of the skill-library and self-reflection patterns. Shipping systems store this as plain files on disk: Claude Code auto memory is a machine-local Markdown directory with a MEMORY.md index (#5), OpenClaw stores USER.md, MEMORY.md and dated daily notes in its workspace with a built-in SQLite hybrid index and can embed with local GGUF, Ollama or LM Studio (#48), and the Agent Skills spec (#22) defines a SKILL.md folder format for playbooks; mem0 (#18) and Letta (#1) are server-shaped and not ranked. None of these methods needs more than a local inference call, so the limit is the quality of the on-device model that does the reflection, not compute.
- **Local retrieval (sub-question 2).** Every store examined is in-process, permissive and alive: LanceDB 0.41.0 (#9, Apache-2.0, Rust core with Python and Node bindings), USearch 2.26.6 (#12, Apache-2.0, single C++11 header with Swift, C#, JS bindings, memory-mapped from disk), FAISS 1.15.1 (#20, MIT), Chroma 1.5.9 (#26, Apache-2.0), sqlite-vec 0.1.9 (#30, Apache-2.0 or MIT, pure C, still pre-v1). Embedding models under Apache-2.0 run from 22.7M parameters (all-MiniLM-L6-v2, 384 dims, #24) through nomic-embed-text-v1.5 (#29) to 0.6B (Qwen3-Embedding-0.6B, #27); EmbeddingGemma claims under 200 MB RAM at 308M parameters (#37) but ships under the Gemma terms, not an OSI license (#34), and its only published latency number is on an EdgeTPU, not a laptop. No primary source gives the memory or disk footprint of any store on a laptop, or laptop embedding throughput; both are listed under Unknowns.
- **Training on-device (sub-question 3).** The only vendor-published laptop measurement is Apple's mlx-lm LoRA doc (#19, file last changed 2026-09-24): Mistral-7B, batch 1, 4 LoRA layers on an M1 Max with 32 GB runs at about 250 tokens per second, which is roughly 900k training tokens per hour if sustained, self-reported with no run count. Unsloth's own table (#2) puts 4-bit QLoRA minimum VRAM at 3.5 GB for 3B, 5 GB for 7B, 6 GB for 8B and 8.5 GB for 14B, so an 8 GB NVIDIA laptop GPU on Windows fits a 7B to 8B QLoRA at batch 1; the one controlled 8 GB study (#36, RTX 4060 desktop card) trained Qwen2.5-1.5B at 500 to 628 tokens per second. PyTorch trains on Mac GPUs through MPS (#17, #10) with no published speed. Apple's own adapter toolkit for the system model (#45) needs a 32 GB Mac, a developer-program download and a retrain for every OS model version, and its 26.0.0 release is declared the last one and incompatible with OS 27. Windows NPU training does not exist for developers: Phi Silica LoRA adapters must be trained in the cloud (#14). ROCm has PyTorch for Radeon and Ryzen on Windows but states training support only for Linux (#46); ONNX Runtime documents on-device training without model-size guidance (#47).
- **Inference runtimes (sub-question 4).** llama.cpp v0.9.0 (#4, MIT) and Ollama v0.40.15 (#6, MIT) run on both platforms and Ollama's FAQ (#16) states that local runs send no prompts to ollama.com and cloud features can be disabled in server.json. Foundry Local went GA 2026-04-09 (#28), runs on Windows, macOS (Apple silicon) and Linux, has an MIT SDK with a proprietary CLI (#7), and its docs (#13) say data never leaves the device with optional diagnostics governed by product terms that this lane did not read, so it is held under Unknowns rather than ranked. ONNX Runtime 1.31.1 (#11, MIT) is the engine under both Foundry Local and Windows ML (GA 2025-09-23, #35; NPU and vendor GPU execution providers need Windows 11 24H2, #8); DirectML is in sustained engineering (#41). MLX 0.32.4 (#15, MIT) is Apple silicon only. Apple's Foundation Models framework gives free on-device access to a roughly 3B model on macOS 26 (#38, #39) but is OS-bound and Mac-only. Windows AI APIs run on Copilot+ PCs (#21, NPU with 40+ TOPS, 16 GB+ RAM) or on RTX 30 and RX 9060 GPUs with 6+ GB in Developer Mode, and Phi Silica is being replaced by Aion Instruct (#14). Whether llama.cpp, MLX, ONNX Runtime, Windows ML or Apple's framework keep any data was not found in a primary source and is listed under Unknowns; only Ollama and Foundry Local publish a statement.
- **Recursive Language Models (sub-question 5).** The paradigm itself is inference-only: a Python REPL holds the long prompt as a variable and the model calls itself on slices, so the loop runs wherever an OpenAI-compatible local server runs (the authors recommend vLLM; the default REPL executes on the host with no sandbox, #23). What does not fit a laptop is the quality floor and the training (#25): the authors report that models without strong coding ability, including base Qwen3-8B, struggle as RLMs; RLM-Qwen3-8B took 48 H100-hours of supervised fine-tuning on 1,000 distilled trajectories; per-query cost with GPT-5 ranged from $0.11 to $0.99 against $0.13 to $0.16 for the base call, cheaper at the median but dearer on average; and the independent reproduction (#32) found depth-2 recursion inflating runtime from 3.6 s to 344.5 s and hurting simple retrieval.

## Options for the planner
Hard requirements, each checked per option below: (1) Platforms: runs on a consumer Apple silicon Mac and on a Windows laptop; a component that covers one platform is ranked only as half of a named Mac-plus-Windows pair, never alone. (2) Data: nothing captured leaves the machine. (3) License: compatible with a repo that may later be MIT and open source. (4) End user: the person never sees a terminal, prompt or model choice, so install and operation must be automatable by the app after permissions are granted. Within a group, options are ordered by the date of their current form, newest first; where two options share a year the one with a measured laptop figure comes first and the line says so.

### A. Learning loop without training (methods and formats, implemented in-app)
1. **Agent Skills format for the playbook store** (spec modified 2026-08-04)
   - What: SKILL.md folders with scripts and references, loaded progressively; the same format Claude Code and OpenClaw read.
   - Platforms: a file convention, both. Data: local files. License: a format, no code license applies. End user: invisible.
   - Tradeoffs: interoperable and human-readable; no provenance model, so untrusted content needs the kind of quarantine OpenClaw documents.
   - Health: specification page, no repo health applies.
   - Evidence: #22, #5, #48
2. **Agentic Context Engineering playbook** (v3 2026-03-29)
   - What: per-workflow playbook of itemized strategies, updated by small deltas from a reflector after each run; no weights change.
   - Platforms: method, both. Data: the reflector is a local model call and the playbook is a local text file. License: paper, no code dependency. End user: invisible.
   - Tradeoffs: no labels needed, auditable, deletable; gains depend on the reflecting model's quality, which on a laptop is a 3B to 8B model.
   - Health: paper, not a package; no reference implementation checked.
   - Evidence: #31, #33, #40
3. **Agent Workflow Memory for workflow induction** (2024-09-11)
   - What: induce reusable workflows from past trajectories, online or offline; the closest published match to "identify recurring workflows".
   - Platforms: method, both. Data: local trajectories. License: paper. End user: invisible.
   - Tradeoffs: evaluated only on web tasks with hosted models; older than the cutoff.
   - Health: paper only.
   - Evidence: #42, #43, #44
