# researcher #2: Self-improvement that is usable on a laptop
STATUS: ISSUES
now: 2026-11-09    stale cutoff: 2026-05-09    lane: 2

## Summary
- **Refinement without training (sub-question 1).** The published line that fits a laptop is context and memory editing, not weight updates: Agentic Context Engineering (v3 2026-03-29, ICLR 2026) keeps an itemized playbook updated by small deltas from execution feedback and needs no labels; GEPA (2026-02-14) and Dynamic Cheatsheet (2025-04-10) do the same for prompts and reusable snippets; Agent Workflow Memory (2024-09-11) induces reusable workflows from past web-task trajectories. Shipping systems store this as plain files on disk: Claude Code auto memory is a machine-local Markdown directory with a MEMORY.md index (docs 2026-11-04), OpenClaw stores USER.md, MEMORY.md and dated daily notes in its workspace with a built-in SQLite hybrid index and can embed with local GGUF, Ollama or LM Studio, and the Agent Skills spec (2026-08-04) defines a SKILL.md folder format for playbooks. None of these methods needs more than a local inference call, so the limit is the quality of the on-device model that does the reflection, not compute. Findings #27 to #37.
- **Local retrieval (sub-question 2).** Every store examined is in-process, permissive and alive: LanceDB 0.41.0 (2026-10-29, Apache-2.0, Rust core with Python and Node bindings), USearch 2.26.6 (2026-10-25, Apache-2.0, single C++11 header with Swift, C#, JS bindings, memory-mapped from disk), sqlite-vec 0.1.9 (2026-03-31, Apache-2.0 or MIT, pure C, still pre-v1), FAISS 1.15.1 (2026-09-16, MIT), Chroma 1.5.9 (2026-05-05, Apache-2.0). Embedding models under Apache-2.0 run from 22.7M parameters (all-MiniLM-L6-v2, 384 dims) to 0.6B (Qwen3-Embedding-0.6B); EmbeddingGemma claims under 200 MB RAM at 308M parameters but ships under the Gemma terms, not an OSI license, and its only published latency number is on an EdgeTPU, not a laptop. No primary source gives laptop embedding throughput. Findings #38 to #47.
- **Training on-device (sub-question 3).** The only vendor-published laptop measurement is Apple's mlx-lm LoRA doc (file last changed 2026-09-24): Mistral-7B, batch 1, 4 LoRA layers on an M1 Max with 32 GB runs at about 250 tokens per second, which is roughly 900k training tokens per hour if sustained, self-reported with no run count. Unsloth's own table (undated page) puts 4-bit QLoRA minimum VRAM at 3.5 GB for 3B, 5 GB for 7B, 6 GB for 8B and 8.5 GB for 14B, so an 8 GB NVIDIA laptop GPU on Windows fits a 7B to 8B QLoRA at batch 1; the one controlled 8 GB study (RTX 4060 desktop card, 2025-09-07) trained Qwen2.5-1.5B at 500 to 628 tokens per second. Apple's own adapter toolkit for the system model needs a 32 GB Mac, a developer-program download and a retrain for every OS model version, and its 26.0.0 release is declared the last one and incompatible with OS 27. Windows NPU training does not exist for developers: Phi Silica LoRA adapters must be trained in the cloud (Learn 2026-10-16). ROCm has PyTorch for Radeon and Ryzen on Windows but states training support only for Linux. Findings #12, #16 to #22.
- **Inference runtimes (sub-question 4).** llama.cpp v0.9.0 (2026-11-04, MIT) and Ollama v0.40.15 (2026-11-03, MIT) run on both platforms and Ollama's FAQ states that local runs send no prompts to ollama.com and cloud features can be disabled in server.json. Foundry Local went GA 2026-04-09, runs on Windows, macOS (Apple silicon) and Linux, has an MIT SDK with a proprietary CLI, and its docs say data never leaves the device with optional diagnostics governed by the product terms (not read). ONNX Runtime 1.31.1 (MIT) is the engine under both Foundry Local and Windows ML (GA 2025-09-23; NPU and vendor GPU execution providers need Windows 11 24H2); DirectML is in sustained engineering. MLX 0.32.4 (MIT) is Apple silicon only. Apple's Foundation Models framework gives free on-device access to a roughly 3B model on macOS 26 but is OS-bound and Mac-only. Windows AI APIs run on Copilot+ PCs (NPU with 40+ TOPS, 16 GB+ RAM) or on RTX 30 and RX 9060 GPUs with 6+ GB in Developer Mode, and Phi Silica is being replaced by Aion Instruct (Insider November 2026, retail January 2027). Findings #1 to #15, #23.
- **Recursive Language Models (sub-question 5).** The paradigm itself is inference-only: a Python REPL holds the long prompt as a variable and the model calls itself on slices, so the loop runs wherever an OpenAI-compatible local server runs (the authors recommend vLLM; the default REPL executes on the host with no sandbox). What does not fit a laptop is the quality floor and the training: the authors report that models without strong coding ability, including base Qwen3-8B, struggle as RLMs; RLM-Qwen3-8B took 48 H100-hours of supervised fine-tuning on about 1,000 distilled trajectories; per-query cost with GPT-5 ranged from $0.11 to $0.99 against $0.13 to $0.16 for the base call, cheaper at the median but dearer on average; and the independent reproduction (2026-03-03) found depth-2 recursion inflating runtime from 3.6 s to 344.5 s and hurting simple retrieval. Findings #24 to #26.

## Options for the planner
Hard requirements: runs on a consumer Apple silicon Mac or a Windows laptop; nothing captured leaves the machine; license compatible with a later MIT open-source repo. Ranked by recency within each group.

### A. Learning loop without training (methods, implemented in-app; nothing to install)
1. **Agentic Context Engineering playbook** (v3 2026-03-29)
   - What: per-workflow playbook of itemized strategies, updated by small deltas from a reflector after each run; no weights change.
   - Fit: meets all three; the reflector is a local model call; stores a text file per workflow.
   - Tradeoffs: no labels needed, auditable, deletable; gains depend on the reflecting model's quality, which on a laptop is a 3B to 8B model.
   - Health: paper, not a package; no reference implementation checked.
   - Evidence: #27, #28, #29
2. **Agent Skills format for the playbook store** (spec 2026-08-04)
   - What: SKILL.md folders with scripts and references, loaded progressively; the same format Claude Code and OpenClaw read.
   - Fit: meets all three; it is a file format.
   - Tradeoffs: interoperable and human-readable; no provenance model, so untrusted content needs the kind of quarantine OpenClaw documents.
   - Health: specification page, modified 2026-08-04; no repo health applies.
   - Evidence: #33, #34, #35
3. **Agent Workflow Memory for workflow induction** (2024-09-11)
   - What: induce reusable workflows from past trajectories, online or offline; the closest published match to "identify recurring workflows".
   - Fit: meets all three as a method.
   - Tradeoffs: evaluated only on web tasks with hosted models; older than the cutoff.
   - Health: paper only.
   - Evidence: #30, #31, #32

### B. Local retrieval store
1. **LanceDB 0.41.0** (2026-10-29): in-process, Rust core, Python and Node bindings, columnar on-disk format. Fit: meets all three. Tradeoffs: broadest feature set; larger binary than the others; 647 open issues. Health: last commit 2026-11-08, release v0.41.0 2026-10-29, 198 releases in 12 months, 647 open issues, archived no, Apache-2.0. Evidence: #39.
2. **USearch 2.26.6** (2026-10-25): single-header HNSW with Swift and C# bindings, memory-mapped indexes. Fit: meets all three. Tradeoffs: index only, no metadata store or persistence of payloads; smallest footprint. Health: last commit 2026-10-31, release v2.26.6 2026-10-25, 16 releases, 115 open issues, archived no, Apache-2.0. Evidence: #41.
3. **FAISS 1.15.1** (2026-09-16): mature index library. Fit: meets all three. Tradeoffs: C++ and Python only, heavier build. Health: last commit 2026-11-07, release v1.15.1 2026-09-16, 9 releases, 379 open issues, archived no, MIT. Evidence: #42.
4. **Chroma 1.5.9** (2026-05-05): Python and JS client with persistence. Fit: meets all three in embedded mode. Tradeoffs: product direction is Chroma Cloud and client-server; latest GitHub release is at the cutoff. Health: last commit 2026-11-07, release 1.5.9 2026-05-05, 24 releases, 979 open issues, archived no, Apache-2.0. Evidence: #40.
5. **sqlite-vec 0.1.9** (2026-03-31): vector search inside SQLite, pure C. Fit: meets all three. Tradeoffs: one file for data and vectors; pre-v1 with breaking changes and last push 2026-05-18, so demoted for activity. Health: last commit 2026-05-18, release v0.1.9 2026-03-31, 20 releases, 249 open issues, archived no, Apache-2.0 or MIT. Evidence: #38.

Embedding models, all Apache-2.0 unless noted: all-MiniLM-L6-v2 (22.7M, card 2026-06-01) for the smallest footprint; Qwen3-Embedding-0.6B (card 2026-04-20) for quality; nomic-embed-text-v1.5 (0.1B, card 2026-04-07) for 8K context. EmbeddingGemma (2025-09-25) is demoted: Gemma terms, not an OSI license, and no laptop latency figure. Evidence: #43 to #47.

### C. On-device inference runtime

Tradeoffs: C library to embed; wide choice of GGUF models; a release per commit, so pin a tag. Health: last commit 2026-11-09, release v0.9.0 2026-11-04, 3,456 releases in 12 months, 2,599 open issues, archived no, MIT. Evidence: #1.

Health: last commit 2026-11-08, release v0.40.15 2026-11-03, 114 releases, 4,621 open issues, archived no, MIT. Evidence: #2, #3.
3. **Foundry Local v2.3.1** (2026-11-03): Fit: meets platform and data requirements; SDK MIT but CLI proprietary and diagnostics governed by product terms not read, so ranked below the fully MIT options. Tradeoffs: 20 MB runtime (self-reported), ONNX model catalog, OpenAI-compatible in-process API, Windows and Mac from one SDK. Health: last commit 2026-11-08, release v2.3.1 2026-11-03, 23 releases, 102 open issues, archived no, MIT (SDK) plus Microsoft Software License Terms (CLI). Evidence: #4, #5, #6.

### D. On-device training
