# researcher #6: Autonomous action boundaries
STATUS: ISSUES
now: 2026-11-09    stale cutoff: 2026-05-09    lane: 6

## Summary
- Provider terms (sub-question 1). The consumer platforms that matter most now name agents explicitly. Amazon's Conditions of Use (2026-08-14) and Uber's U.S. Terms (2026-11-04) both add "Agent Terms": an agent must declare itself in the HTTP user agent, must not mimic human input or complete CAPTCHAs, must stop when asked, and Uber users may not share credentials with an agent Uber has not authorized (#10, #12). Chase's terms name "AI agents or agentic AI" as unauthorized entry (#45) and Bank of America's online banking agreement (effective 2026-10-19) forbids letting a third party use the service or hold your credentials except under guardianship or power of attorney (#1). Google's terms (2026-07-30) and Microsoft's (effective 2026-09-30) ban automated access that violates robots.txt or circumvents access limits, but both offer sanctioned APIs: Gmail API, Calendar API and Microsoft Graph (#7, #8, #14, #5, #18). Gmail's restricted OAuth scopes require verification and, when data passes through a third-party server, an annual third-party security assessment (#2). Two utilities (Entergy 2026-02-12, Dominion) bar robots and scrapers and publish no API (#22, #46). DocuSign bans scraping and circumvention and publishes the eSignature REST API (#33, #34); Buildium's Open API needs a Premium subscription (#47); AppFolio integrates only through its Stack marketplace (#48). No utility, bank or Uber page offered an official consumer API for an agent to pay a bill or book a ride; the sanctioned paths are OAuth APIs for mail and calendar, Plaid-style consented access for bank data, and the card networks' agent programs for payments.
- 2FA and CAPTCHA (sub-question 2). The CAPTCHA vendors describe their job as separating humans from automated traffic (Turnstile #11, reCAPTCHA #21, hCaptcha #24), and the two largest consumer sites now make solving a CAPTCHA by an agent a terms violation (#10, #12). The sanctioned alternative is to identify the agent: Cloudflare Web Bot Auth and signed agents (#4, #30) and the Amazon and Uber user-agent rules. For 2FA, FIDO says today's authentication models "were designed for direct human interaction, not delegated, agent-initiated actions" and started an Agentic Authentication working group on 2026-04-28 (#17). Shipping agents hand the moment back: OpenAI pauses and asks the user to take over the browser for logins and stops screenshots while they type (#36); Google's auto browse can use Google Password Manager if given permission and otherwise prompts the user (#23); 1Password for Agents (2026-10-22) has the user approve each credential on their own device and fills the form itself so the model never sees the password (#3, #29); Copilot Studio asks the maker to choose maker-provided or end-user credentials (#40).
- Unattended versus draft-and-confirm (sub-question 3). Every shipping agent read here confirms before a purchase or payment: Google's auto browse "is designed to pause and explicitly ask for your confirmation" before purchases or posting (#23), Google agentic checkout buys "only after you've confirmed the purchase and shipping details" (#26), Anthropic's Claude in Chrome "asks users before taking high-risk actions like publishing, purchasing, or sharing personal data" and blocks high-risk site categories (#25, #38), OpenAI's agent uses "user confirmations for high-impact actions" and a watch mode on sensitive sites such as financial institutions (#36, #37), and Anthropic's computer-use docs tell developers to require human confirmation for "completing financial transactions, or agreeing to terms of service" (#39). Microsoft runs Windows agents in a separate standard account with per-agent permissions and consent prompts for folders (#27, #28). None of these products ships unattended money movement or unattended deletion of mail as a default.
- Credentials and payment instruments (sub-question 4). Credentials: 1Password for Agents (2026-10-22, consumer) and Secure Agentic Autofill with Browserbase (2025-10-08, enterprise, cloud browser) keep the secret out of the model and gate each use on a human approval (#3, #29); OpenAI's takeover mode and Google Password Manager are built into those vendors' own browsers (#36, #23). Payments: Visa Intelligent Commerce (launch 2025-04-30, Connect pilot 2026-04-08) requires an approved participant to onboard to the Trusted Agent Protocol, Visa Token Service and Visa Payment Passkeys (#20, #31, #43); Mastercard Agent Pay (2025-04-29) requires agents to be "registered and verified" and gives consumers control over what the agent may buy (#32); Google's AP2 v0.2.0 (2026-04-28) anchors payments to signed user mandates (#16); OpenAI and Stripe's Agentic Commerce Protocol is in beta and Stripe issues Shared Payment Tokens as scoped credentials for agent purchases (#15, #42); UCP (release 2026-08-25) is the Google-Shopify merchant-side protocol (#9, #44). Virtual and single-use cards for agents: no primary source found; an unknown.
- Legal leads (sub-question 5). ESIGN §7001(h) says a contract may not be denied effect because "one or more electronic agents" formed it, so an agent-signed lease is not void on that ground (#52), with UETA §14 the state-law counterpart (#53, text not read). Regulation E's official interpretation makes a consumer who gives an access device and authority to another person "fully liable" for that person's transfers until the bank is notified (#51), which is the liability an agent using the user's bank login would create. A product that only acts as a payment processor by agreement with the creditor is excluded from the FinCEN money transmitter definition; holding or routing the user's funds itself is the line to stay behind (#54). The CFPB open-banking rule (12 CFR 1033) is final but enjoined and under reconsideration, so consented third-party bank access has no enforceable compliance date (#35, #19). The Ninth Circuit (2026-08-04) held that the user, not the agent vendor, "accesses" a site under the CFAA, but left terms-of-service claims open, so the provider terms above remain the operative constraint (#13).

## Options for the planner
Hard requirement for ranking: a primary source (the provider's own terms, policy or docs) with a date. Options are grouped by the decision they feed; within a group the newest current form ranks first.

Group A: how the agent logs in to third-party sites.
1. **1Password for Agents** (2026-10-22)
   - What: the agent authenticates to 1Password with a key; the end user approves each credential on their own device; 1Password fills the form; the model never sees the secret.
   - Fit: meets the primary-source requirement; keeps secrets off the model; requires the end user to hold a 1Password.com-hosted account and to approve on a device, so it is draft-and-confirm at login, not unattended; whether third-party desktop agents can integrate today is not stated on the page.
   - Tradeoffs: the strongest consumer answer to credential custody; adds a paid account and a per-login approval.
   - Health: service, not a package.
   - Evidence: #3, #29.
2. **Pause-and-take-over pattern** (OpenAI help pages undated; Anthropic docs undated; Google 2026-01-28)
   - What: the agent stops at a login or 2FA prompt, the human types the credential or code, screenshots stop during takeover, then the agent resumes.
   - Fit: meets the requirement (vendor docs); works with any site; by construction it is not unattended.
   - Tradeoffs: zero integration cost; blocks on the user at every login unless a session persists.
   - Health: pattern, not a package.
   - Evidence: #36, #37, #38, #39, #40.
3. **Secure Agentic Autofill with Browserbase** (2025-10-08)
   - What: 1Password extension running inside a Browserbase cloud browser with human approval per use.
   - Fit: meets the requirement; demoted: runs in a cloud browser, so the session leaves the machine, which the owner's retention constraint forbids by default; enterprise plans only; older than the cutoff.
   - Health: service.
   - Evidence: #29.

Group B: how the agent pays.
1. **AP2 v0.2.0** (2026-04-28)
   - What: Google-led open protocol; signed user mandates carry intent to the merchant and network; donated to FIDO.
   - Fit: meets the requirement; Apache-2.0 fits a later open-source release; needs a payments partner to settle, so it does not by itself give Halvo a card to use.
   - Health: last commit 2026-06-17, latest release v0.2.0 (2026-04-28), 1 release in 12 months, 190 open issues, archived no, license Apache-2.0.
   - Evidence: #16, #17.
2. **Universal Commerce Protocol** (release 2026-08-25)
   - What: Google and Shopify merchant-side protocol for discovery, cart and checkout; Shopify ships a CLI.
   - Fit: meets the requirement; Apache-2.0; covers the merchant side of an Amazon- or Uber-style purchase only where the merchant adopts it.
   - Health: last commit 2026-11-09, latest release v2026-08-25, 4 releases total, 265 open issues, archived no, license Apache-2.0.
   - Evidence: #9, #44, #42.
3. **Agentic Commerce Protocol with Stripe Shared Payment Tokens** (repo pushed 2026-07-18)
   - What: OpenAI and Stripe open standard, in beta; Stripe issues scoped payment credentials for agent-initiated purchases.
   - Fit: meets the requirement; Apache-2.0; beta with no tagged release.
   - Health: last commit 2026-07-18, latest release none, 0 releases in 12 months, 147 open issues, archived no, license Apache-2.0.
   - Evidence: #15, #42.
4. **Visa Intelligent Commerce** (Connect pilot 2026-04-08; launch 2025-04-30)
   - What: network-level agent program with tokenized credentials, consumer purchase instructions and agent validation.
   - Fit: meets the requirement; demoted because the developer docs require approved-participant status and onboarding to TAP, VTS and Visa Payment Passkeys, which a pre-launch product cannot assume; Connect is a pilot.
   - Health: service.
   - Evidence: #20, #31, #43.
5. **Mastercard Agent Pay** (2025-04-29)
   - What: Agentic Tokens; agents must be registered and verified; consumer sets purchase limits.
   - Fit: meets the requirement; older than the cutoff and the press release page blocks curl; no public developer onboarding read.
   - Health: service.
   - Evidence: #32.

## Learnings
- The Wayback Machine URL form `web.archive.org/web/<year>/<url>` (without `id_`) returns full page text with HTTP 200 for sites that block curl; the `id_` raw form returned shells for these pages.
- Terms pages for banks, Amazon and Uber now name agents directly, so a report on automation boundaries should grep for "agent" before "robot" or "scraper".
- Microsoft, Google and Cloudflare docs carry machine-readable `dateModified` or "Last updated" strings; vendor help centers (Intercom) and legal pages often do not, so "unknown" dates cluster there.
