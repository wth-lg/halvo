# R1 gate pre-measurement baseline (P6 integration, sub-check (e): daemon memory).
#
# The P0 memory bound for the capture daemon's resident set. check-memory.sh
# gates the daemon's peak and mean RSS against rss_max_bytes below.
#
# How measured (perf-check / explain-number):
#   Binary: the halvo-capture DEBUG binary, which is what the gate runs through
#           `cargo run`, so the bound matches the gate's own measurement.
#   Load:   `--timed-run` with the screen, input and foreground sources active,
#           a 2 Hz synthetic input load (mouse + keystrokes), persisting
#           encrypted segments to a store (the full wired pipeline).
#   Sample: daemon RSS once per second via `ps -o rss= -p <pid>`, sampling the
#           capture process's own pid (written to HALVO_PID_FILE), not a wrapping
#           shell.
#   Host:   this Mac (aarch64-apple-darwin), 2026-11-09.
#
# Pre-measurement over a 25 s run (25 samples):
#   peak_rss_bytes=25231360   (24.1 MiB)
#   mean_rss_bytes=25116672   (24.0 MiB)
# Peak == mean to within one percent, which confirms the resident set is
# bounded: the sink is a bounded channel and the daemon flushes each batch at
# SEGMENT_BATCH_MAX events rather than buffering a capture window.
#
# The bound is the measured peak with roughly 2x headroom for run-to-run and
# 600 s-run variance. A bounded daemon (~24 MiB) passes; a daemon that buffered a
# whole capture window (hundreds of MiB) fails. 48 MiB = 50331648 bytes.
rss_max_bytes=50331648
